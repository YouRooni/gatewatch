# Gatewatch

## 2026-11-06

- Новый проект: центр событий, агент, источники journald/файл/demo, канал Telegram.
- Протокол v1 не зависит от ОС; источники и каналы подключаются через entry points.
- SQLite WAL, атомарная фиксация курсора с очередью, дедупликация на центре и независимые доставки каналов.
- Привязка по UUID ноды и ID темы; переименование сохраняется, удаление восстанавливается при отправке.
- По отдельному запросу добавлен отключённый по умолчанию PAM-захват ошибочных паролей. Успешные пароли отбрасываются в памяти; решения о блокировке берутся только из Fail2ban.
- Локальные секреты и отчёты хранятся в игнорируемом tmp/.
- Подготовлены установка systemd, документация, тесты и CI.
- Развёрнуты центр, два агента Debian 12 и отдельная Demo-нода. Конфигурации и адреса экземпляра остаются вне репозитория.
- По уточнениям: успешные входы не уведомляются по умолчанию, название сервера только в теме, тема «имя - IP», дата показывается только при задержке, веб-превью отключены.
- Проверены настоящие Rich-сообщения, восстановление удалённой тестовой темы и обновление одной карточки при повторной попытке.
- PAM проверен отдельно: верный/неверный пароль, отключённый приёмник, настоящий изолированный sshd. Успешный пароль отсутствует в очереди агента и БД центра. Все временные учётные записи и тестовый sshd удалены.
- 47 автоматических тестов. CI: Debian 12, Ubuntu 22.04/24.04, Windows, Python 3.10/3.13; в Debian отдельный PAM integration check.
- Изолированный тест SQLite: 10 000 событий + 10 000 повторов, 100 карточек, 2,676 с, пик RSS процесса 21,8 МиБ. Это не замер Telegram/network throughput.
- Изменения безопасности реального экземпляра: включён Fail2ban SSH на основном центре, OpenSSH обновлён на двух машинах с сохранением конфигов и проверкой нового входа. Бекапы хранятся вне репозитория.
